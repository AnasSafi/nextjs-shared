CONSUMER TASK – Use native initialSorts in shared table components (remove local fork)

Goal:
- Stop using consumer-side `TablePagesCore` fork for default sorting.
- Use built-in `initialSorts` support from `@nextjs-shared/shared`.
- Remove `__initialSorts` workaround from `requestBodyData`.

What changed in shared:
- `initialSorts?: SortModel[]` was added to:
  - `TableProps<R>`
  - `ListPageProps<R>`
- `TablePagesCore` now:
  - initializes `pagination.sorts` from `initialSorts` on first render
  - normalizes invalid values:
    - ignores items with empty `field`
    - `operation` is only `asc | desc` (fallback is `desc`)
  - if `initialSorts` changes later, applies it only when current sorts are empty
  - never overrides user-selected sorts

1) Remove local table fork logic

- Delete/stop using consumer custom `TablePagesCore` fork made only for initial sort.
- Remove any payload hack like:
  - `requestBodyData.__initialSorts`
  - stripping `__initialSorts` before request

2) Pass initialSorts directly to ListPage (recommended)

```tsx
<ListPage
  apiPath="/api/orders/list"
  columns={columns}
  initialSorts={[{ field: "createdAt", operation: "desc" }]}
  ...
/>
```

3) Or pass initialSorts directly to TablePagesCore

```tsx
<TablePagesCore
  data={data}
  setData={setData}
  apiPath="/api/orders/list"
  columns={columns}
  initialSorts={[{ field: "createdAt", operation: "desc" }]}
  ...
/>
```

4) Important behavior notes

- `initialSorts` is for initial/default state only.
- If user already selected sorting, later `initialSorts` prop updates will not overwrite it.
- To allow re-applying new `initialSorts`, the current sorts must be empty.

5) Verify

- Open list page first time:
  - confirm API receives pagination.sorts with expected default sort.
- Change sort from UI:
  - confirm user sort is preserved and not overridden by prop changes.
- Remove all sorts from UI (empty state), then change `initialSorts`:
  - confirm new initial sort is applied.
- Confirm no `__initialSorts` key is sent in requests.

DONE CRITERIA:
- Consumer no longer depends on local `TablePagesCore` fork for initial sort.
- Consumer no longer uses `__initialSorts` in request body.
- Default sorting works via shared `initialSorts` API.
